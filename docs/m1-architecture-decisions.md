# Module 1: Architecture Decision Records (ADRs)
**Date:** 2026-10-01

## ADR 1: Asynchronous Processing via Cloudflare Queues
*   **Context:** `POST /match/run` blocks the HTTP request while calling NVIDIA `meta/muse-glimmer-30b`, risking HTTP timeouts (Cloudflare 100s limit) and breaking UX.
*   **Decision:** Migrate all heavy AI extraction and matching workloads to Cloudflare Queues. The API will immediately return a `job_id`, and the client will poll `GET /match/status/:job_id` or subscribe via SSE.
*   **Consequences:** Requires provisioning `M1_JOBS` Queue and updating the frontend to support an explicit `VALIDATING -> EXTRACTING -> MATCHING -> READY` state machine.

## ADR 2: ATS Document Signal Extraction
*   **Context:** The previous ATS score was an arbitrary percentage generated by the LLM, violating the "deterministic signal" rule.
*   **Decision:** Implement a deterministic algorithm in the Python Pyodide worker (`resume-extractor`) that evaluates parseability (PDF text layer integrity, missing headers, unreadable tables). The AI will solely be responsible for Semantic Job Alignment, NOT ATS parsing scores.
*   **Consequences:** Clear separation between structural ATS parseability and semantic job match.

## ADR 3: Universal Evidence Schema Expansion
*   **Context:** Currently, `candidate_context` stores a raw JSON blob. We need formal lineage and contradiction handling.
*   **Decision:** Introduce `evidence_item` table storing `normalized_value`, `evidence_status` (13 enum states), `confidence`, and `source_span`.
*   **Consequences:** Enables the Contradiction Engine to flag specific rows for human review.
